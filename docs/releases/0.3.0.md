# Flere 0.3.0

Flere is the new name for Railhand. This release uses `flere` and
`flere-connect`, a new Open Orbital logo and the FLERE intro wordmark.

## Clean installation

This is a fresh namespace: package IDs, protocol identity, hooks, environment
markers, project icon paths and private directories all use Flere. It does not
migrate or attach to old Railhand state. Existing Railhand commands and data can
remain as a backup. Normal Flere updates within the new namespace still preserve
running sessions through the managed installer.

On Linux/macOS, the first-use installer prepares the core and SSH companion.
Windows has a local companion with both `flere.exe` and `flere-connect.exe`
stable launchers; the terminal workbench itself runs on a supported remote Unix
host. `flere ssh HOST` uses existing OpenSSH settings, discovers the remote target,
installs a verified core only when absent, starts the supervisor without a native
chat, and attaches. Compatible installations are reused; uncertain or incompatible
state requires an explicit decision.

## In the terminal

- Workspace cards group by Status or Project, with a Primary badge and context menus.
- Split panes have separate tabs and share views across attached windows.
- The image gallery supports h/j/k/l and arrows. Screenshots capture the complete
  composed workbench and place the PNG plus a retained path on the local clipboard.
- Flere is the default pet and wandering intro mascot. Petting changes its emotion
  field; dragging throws it. Mouse movement and clicks keep the screensaver open.
- **Context Ruins** is an optional original platform adventure with playable
  mascots, ladders, keys and hazards. It stays inside the terminal renderer.

## Distribution and evidence

The publication candidate is prepared locally before any public release. Refer
to the adjacent platform manifests and SHA256SUMS for exact package identities.
The [validation record](0.3.0-validation.md) distinguishes complete baseline tests,
final targeted checks, actual installation proof and remaining physical acceptance.
The selected HTTPS channel is the trust root; SHA-256 checks detect corruption
and are not an independent publisher signature. macOS artifacts are not Developer
ID notarized. No self-update is inferred from running an ordinary Cargo build.

Linux x86_64 is the first supported target. macOS arm64 has runtime validation;
Intel macOS and Windows checks must be described at the level actually performed.
Physical Windows clipboard/image/font/cleanup and native chat acceptance remain
tracked in [the acceptance checklist](../acceptance.md). Old Railhand test counts
and historical screenshots are not proof of this new build.
